# 创意照片应用｜产品与架构基线 v0.2

## 决策归属与当前 Stage

项目所有者提供的 DeepSeek Harness Prompt 确定了当前 **Stage 01：Project Foundation and iOS Application Skeleton**，且已交给 DSH 执行。本文件仅作为 Architect 基线及交付后 Review 依据，不修订正在执行的原始 Prompt。此前把 Stage 1 定义为完整拼贴闭环的方案已撤回，不作为执行依据。

Stage 01 只交付可运行的 SwiftUI 应用骨架：首页、创建项目、编辑器占位页、设置占位页、基本导航、最小项目状态、可序列化的基础模型、必要测试和工程文档。**不做真实图片导入、拼贴画布或导出。** 占位页必须明确写“尚未实现”，不能伪装已完成的功能。

Stage 状态按 `SPEC_READY → IMPLEMENTING → READY_FOR_ARCHITECT_REVIEW → WAITING_FOR_USER → APPROVED` 推进。DSH 完成代码和测试后只可报告 `READY_FOR_ARCHITECT_REVIEW`；ChatGPT 完成架构、Bug、性能和视觉 Review，并确认有可运行版本与验收说明后，才转为 `WAITING_FOR_USER`。用户修改意见使状态成为 `CHANGES_REQUESTED`。只有项目所有者明确说“通过”可转为 `APPROVED`，随后才能定义/执行下一 Stage。

## 产品主线与范围

长期用户路径：多图导入 → 每张照片分析 → 结构化角色与布局建议 → 对每张图自适应统一视觉风格 → 用户完整编辑 → 静态导出。轻量动效与视频导出属于静态产品稳定后的独立阶段。目标是可正式上架的 iPhone 优先应用，iPad 适配留在后续验收。

目前只批准 Stage 01 的基础工程。DSH Prompt 中的 Stage 02–15 是**待重新定义的路线图草案**，不是自动获批的工作队列。静态导出应在完整编辑与动态效果之前建立并验收，具体 Stage 编号留到 Stage 01 通过后决定；不能把动态系统建在没有静态渲染与导出真相的基础上。

## 模块边界

```text
SwiftUI 屏幕与导航
    ↓ 用户动作
ProjectStore → Project / CanvasDocument / Asset / Layer (Codable)

未来：PhotoAnalyzer → CompositionPlanner → ProjectDocument → RenderEngine
                                                  ↑
                                    AssetLoader(preview / original)
```

- **Stage 01 UI**：只负责展示、导航和发起创建/重命名/打开项目动作，不写图像处理逻辑。
- **ProjectStore**：Stage 01 可用内存实现近期列表，但若界面宣称“最近项目”可恢复，则必须确实持久化。内存列表应显式标注为本次运行内的数据；不要悄悄丢失后仍显示为永久草稿。存储实现留出以后复制原图到沙盒并以相对路径引用的空间。
- **基础模型**：`Project` 有身份、名称、创建/修改时间和文档；`CanvasDocument` 有画布描述与图层列表；`Asset` 描述素材的本地引用；`Layer` 描述图层身份、类型与基本展示属性。Stage 01 只建实际可解释、可 `Codable` 的字段；不提前承诺复杂图层、AI 或渲染字段为公共 API。模型的更改需经 Architect Review。
- **未来 PhotoAnalyzer**：只产出每图测量、置信度和失败原因，不直接改图。
- **未来 CompositionPlanner**：只产出结构化、可编辑的角色、布局、裁切和逐图调整建议，不能直接控制最终像素，不能覆盖用户锁定编辑。
- **未来 RenderEngine**：同一文档几何数据分别消费预览素材与原始素材。SwiftUI 视图截图不能作为最终导出结果。

不预建空服务、空协议、大型依赖或多个 Swift Package。目录依据实际代码出现；用户 Prompt 要求的治理文档保留，但内容要短、真实。

## 后续 AI 与图像决策原则

分析输入至少考虑主体/显著区域、构图、视觉权重、色彩、曝光、色温、饱和度、高光、阴影、清晰度及人像肤色风险。角色可包括主拼贴图、次要照片、可抠主体、剪影/贴纸候选及暂不使用。角色选择必须可解释、可回退；低置信度遮罩降级为普通照片。

风格统一采取**目标观感 + 每图状态测量 + 独立调整量**。不能对所有照片应用同一参数组；过暗与过曝照片应得到不同方向的调整。保护肤色和高光。AI 输出序列化提案，用户接受后成为可手动编辑的普通项目数据；重新生成不得静默覆盖用户改动。

本地优先。云模型是否引入，需单独评估隐私、成本、离线退化、告知及数据流，当前不决定。重计算离开 UI 主线程，预览用缩小素材，最终导出用原始素材，原图不可被破坏性修改。

## 视觉与交互基线

Stage 01 使用中性、清楚的 iOS 原生外壳。照片在未来编辑器中应是第一视觉焦点；当前占位页不应模仿完成态。系统字体、SF Symbols、合适的安全区域和至少 44×44 pt 的主要触控区域。导航可返回，创建项目有即时反馈；VoiceOver 应读出按钮含义。禁止霓虹、紫蓝 AI 渐变、过量玻璃材质、满屏卡片、无意义动画及 Web 控制台布局。最终品牌风格仍待所有者验收。

设计数据检索对“创意照片 iOS 编辑器”返回了偏网站/Dashboard 的配色与结构，SwiftUI 手势查询无匹配；这些结果不采用。以上方向来自用户要求与原生移动端基本规范。

## 技术与上架核对

后续照片选择优先评估 Apple 的 [PhotosPicker](https://developer.apple.com/documentation/photosui/photospicker)：它允许用户明确选择照片，不需要为选中项申请整个图库权限。最终导出要评估独立渲染管线；Apple 的 [ImageRenderer](https://developer.apple.com/documentation/swiftui/imagerenderer)仅能导出 SwiftUI 实际绘制内容，混用某些 UIKit 内容时可能显示占位。人物遮罩可评估 [Vision](https://developer.apple.com/documentation/vision/vngeneratepersonsegmentationrequest)，逐图调色可评估 [Core Image](https://developer.apple.com/documentation/coreimage/color-adjustment-filters)。这些候选技术不属于 Stage 01 的实现许可。

正式提审前按届时有效的 [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)检查隐私、权限、性能、元数据与内容要求。Stage 01 文档只能记录待核验项，不能宣称已经符合上架要求。
